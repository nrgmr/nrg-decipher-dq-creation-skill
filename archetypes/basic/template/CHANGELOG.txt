__DQ_NAME__ v__VERSION__ - change log
=====================================

Scaffolded from the `basic` archetype. Self-contained: no runtime file is
imported from another version.

The package runtime files carry no explanatory comments, by convention. This file
is where the reasoning lives, because an operator needs version behaviour without
access to the conversation that produced it.


What this version does
----------------------
Presents the adopting question's rows as selectable cards and records, per row,
the order in which the respondent first touched it.

Designer surface: see IMPORT.md, which is generated from spec.json and the demo.
Do not document parameters here as well; two copies drift.


Capture
-------
One variable, __DQ_UPPER___ORDER, text, one row per question row.

Text rather than number, deliberately: an `input type="number"` silently discards
a non-numeric write, and the empty string is a meaningful value here ("never
touched"). A number field would coerce it.

The block is generated from the demo survey by `dq.py extract`, and identifies
itself by a hash of its own declarations. There is no version number to forget to
bump.
